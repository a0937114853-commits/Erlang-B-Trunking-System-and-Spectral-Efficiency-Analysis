## 1. Erlang-B 公式遞迴實作與話務量計算
* **數值穩定性處理**：直接計算傳統 Erlang-B 公式中的階乘 m! 與 ρ<sup>m</sup> 容易在大頻道數（如 m = 200）時造成數值溢位 (NaN)。本專案採用數值穩定的遞迴倒數關係式進行優化：
  `1 / B(ρ, m) = 1 + (m / ρ) * (1 / B(ρ, m - 1))`
* **話務量求解**：透過 MATLAB 的 `fzero` 函數，針對指定的頻道數與阻斷率（1%, 3%, 5%, 10%），精確求解出系統所能提供的總話務量 (ρ)。

| 頻道數範圍 (m) | 求解方法 | 目標阻斷率 |
| :---: | :---: | :---: |
| 1 ~ 20, 200 ~ 220 | 遞迴 Erlang-B + `fzero` | 1%, 3%, 5%, 10% |

## 2. 提供話務量與實際攜帶話務量解析
* **提供話務量大於頻道數之原因**：提供話務量（ρ = λμ）代表系統的總話務需求（即用戶撥話需求總量），而頻道數 (m) 則是物理線路的上限。在允許一定阻斷率（如 1% ~ 10%）的忙時系統中，總需求經常會超過實體頻道數，此時系統會達到最大容量並阻斷多餘用戶。
* **實際攜帶話務量 (A<sub>c</sub>) 之計算**：
  * 成功被系統服務的實際話務量為總提供話務量乘以呼叫成功的機率：
    `A_c = ρ * (1 - B(ρ, m))`
  * 從統計學角度來看，亦等於穩態下忙碌通道數的期望值：
    `A_c = Σ (k * P_k)` （從 k = 0 到 m）

## 3. 頻率重複與頻譜效率評估
* **系統設定**：假設總共有 600 個頻道，分別由 1 個、2 個或 3 個營運商平分，並使用頻率重複因子 N = 5。
* **每細胞頻道數 (C<sub>cell</sub>)**：
  * 1 個營運商：C<sub>cell</sub> = (600 / 1) / 5 = 120 個頻道
  * 2 個營運商：C<sub>cell</sub> = (600 / 2) / 5 = 60 個頻道
  * 3 個營運商：C<sub>cell</sub> = (600 / 3) / 5 = 40 個頻道
* **頻譜效率分析**：將所有 600 個頻道集中由單一營運商管理可形成更大的群組尺寸（Trunk Size），在相同阻斷率下能提供更高的每頻道話務量 (G<sub>c</sub> = ρ / C<sub>cell</sub>)，因此**單一營運商架構具備最高的主幹效率與頻譜效率**。
